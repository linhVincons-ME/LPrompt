## 2. Lỗi cần sửa

### 2.1. (Nghiêm trọng) Content script build ra có `import`, nên không chạy trên Gemini

**Nguyên nhân:** `vite.extension.config.ts` build 3 entry chung một lần: `sidepanel`, `contentScript` và `serviceWorker`. `availability.ts` giờ được cả `contentScript.ts` lẫn `ExtensionPanel.tsx` import, nên Rollup tách nó ra `chunks/availability-lTXgGQ-l.js`, và `contentScript.js` import chunk đó. Trong khi đó, `content_scripts` của cả hai manifest đều là script thường.

**Bằng chứng:**

```
$ head -c 60 extension-dist/contentScript.js        (bản trên máy bạn)
import{t as e}from"./chunks/availability-lTXgGQ-l.js";…

$ node -e "new (require('vm').Script)(fs.readFileSync('extension-dist/contentScript.js','utf8'))"
SyntaxError: Cannot use import statement outside a module
```

**Vì sao test không bắt được:** test mới trong `extensionSafety.test.ts` dùng regex `/^import\s/m`. Bản build đã được nén thành `import{` (không có khoảng trắng sau `import`), nên regex không khớp và test vẫn qua. Ngoài ra, test này đọc `extension-dist/`, là thư mục bị `.gitignore`. Trong CI, `npm run check` chạy test **trước** build extension, nên trên một bản checkout mới test sẽ lỗi `ENOENT`. Tôi đã thử: xóa `extension-dist` rồi chạy test thì có 1 test lỗi ENOENT. Kết quả là CI trên GitHub sẽ đỏ.

**Đề xuất (đã thử trên bản sao):** build content script riêng dạng IIFE.

1. Bỏ dòng `contentScript: resolve(...)` khỏi `input` trong `vite.extension.config.ts` và `vite.extension.firefox.config.ts`.
2. Tạo `vite.extension.content.config.ts`:

```ts
import { resolve } from 'node:path';
import { defineConfig } from 'vite';

// Content script phải là classic script (không có import), nên build riêng dạng IIFE.
export default defineConfig({
  publicDir: false,
  build: {
    outDir: 'extension-dist',
    emptyOutDir: false,
    lib: {
      entry: resolve(import.meta.dirname, 'extension/contentScript.ts'),
      formats: ['iife'],
      name: 'LPromptContentScript',
      fileName: () => 'contentScript.js'
    }
  }
});
```

3. Thêm bước này vào script build trong `package.json`:

```json
"build:extension:chrome":  "tsc -p tsconfig.extension.json && vite build --config vite.extension.config.ts && vite build --config vite.extension.content.config.ts",
"build:extension:firefox": "tsc -p tsconfig.extension.json && vite build --config vite.extension.firefox.config.ts && vite build --config vite.extension.content.config.ts --outDir extension-dist-firefox",
```

Tôi đã thử trên bản sao: `contentScript.js` thành một file IIFE 4,96 kB, parse được dạng script thường và có đủ logic `classifyTransientFailure`. Thư mục `chunks/` không còn, và `serviceWorker.js` vẫn không có `import`.

4. Sửa test để kiểm tra đúng cách, và chạy test sau khi build:

```ts
import vm from 'node:vm';
it('built content scripts parse as classic scripts', () => {
  for (const dir of ['extension-dist', 'extension-dist-firefox']) {
    const code = readFileSync(new URL(`../${dir}/contentScript.js`, import.meta.url), 'utf8');
    expect(() => new vm.Script(code)).not.toThrow();   // bắt cả "import{" đã nén
  }
});
```

Đổi `"check"` thành `npm run lint && npm run build && npm run build:extension && npm run test`, hoặc tách test bản build sang một script riêng `test:dist` chạy sau build.

**Lưu ý thêm:** Firefox nạp `serviceWorker.js` qua `background.scripts`, cũng là script thường. Nếu sau này `serviceWorker.ts` import code dùng chung với panel, lỗi y hệt sẽ xảy ra ở service worker. Nên áp dụng cùng test `vm.Script` cho `serviceWorker.js` của bản Firefox.

**Sau khi sửa:** build lại và reload extension. Bản hiện đang cài trên trình duyệt của bạn (build lúc 15:49) không chèn được prompt vào Gemini.

### 2.2. (Cao) `db.transaction` không tồn tại trong `node:sqlite`, nên xóa prompt luôn lỗi

**Vị trí:** `server/db.js`, `deletePrompt`.

```
$ node -e "import('./server/db.js').then(m => { m.initDatabase(); m.deletePrompt('x') })"
DELETE FAIL: db.transaction is not a function
```

Các phương thức có trên `DatabaseSync` (Node 22.22) là `open, close, prepare, exec, function, aggregate, createSession, applyChangeset, enableLoadExtension, loadExtension`. Không có `transaction`. Theo những gì tôi biết, Node 24 cũng không có. Bạn có thể kiểm tra trên máy bằng lệnh: `node -e "const {DatabaseSync}=require('node:sqlite');console.log(typeof new DatabaseSync(':memory:').transaction)"`.

**Hậu quả:** `DELETE /api/prompts/:id` trả 500. Web app xóa cục bộ rồi đưa yêu cầu vào outbox. Outbox thử lại mỗi 30 giây nhưng lần nào cũng thất bại, nên prompt vẫn còn trong SQLite và hàng đợi không bao giờ hết.

**Đề xuất:**

```js
export function deletePrompt(id) {
  db.exec('BEGIN');
  let result;
  try {
    db.prepare('DELETE FROM prompt_versions WHERE prompt_id = ?').run(id);
    result = db.prepare('DELETE FROM prompts WHERE id = ?').run(id);
    db.exec('COMMIT');
  } catch (error) {
    db.exec('ROLLBACK');
    throw error;
  }
  autoBackupSnapshot();
  return { success: result.changes > 0, id };
}
```

Nên thêm vào `server.integration.test.js` một bước `DELETE /api/prompts/:id` và kiểm tra version có `promptId` cũng bị xóa. Hiện chưa có test nào gọi API xóa prompt, nên lỗi này lọt qua.

### 2.3. (Trung bình) Phủ định "chữ" cắt nhầm từ ghép, có thể đảo nghĩa câu

**Vị trí:** `src/services/constructionPromptCompiler.ts`, `textTerms`.

Cách loại trừ hiện tại chỉ áp dụng cho "ký" (`(?!\s+ký…)`). Mọi từ ghép khác của "chữ" vẫn bị cắt:

```
"Không có chữ số trên cột"        → giữ lại "số trên cột"          ❌ (nghĩa bị đảo: thành "có số trên cột")
"Không có chữ viết tay trên bảng" → giữ lại "viết tay trên bảng"   ❌
"Không có chữ in trên áo"         → giữ lại "in trên áo"           ❌
"Không có text box"               → giữ lại "box"                  ❌
"Không có âm thanh nào, nền xanh" → giữ lại "nào, nền xanh"        (lỗi nhẹ: phần âm thanh chưa nuốt "nào")
```

**Đề xuất (đã thử trên bản sao):** thay vì liệt kê từ cần loại trừ, chỉ coi "chữ/text/phụ đề/watermark" là đối tượng của câu phủ định khi ngay sau nó là **cuối mệnh đề**: hết câu, dấu câu, "và/hoặc/hay/nào", hoặc "lên/trên/ở".

```ts
const CLAUSE_END = '(?=\\s*(?:$|[,.;:!?]|(?:và|hoặc|hay|nào|lên|trên|ở)(?![\\p{L}\\p{N}])))';
const textTerms = `(?:phụ đề|watermark|text|chữ(?:\\s*trên\\s*(?:ảnh|video))?)${END}${CLAUSE_END}`;
// và thêm (?:\\s+nào)? sau ${mediaTerms} trong negatedMedia
```

Kết quả thử:

```
"Không có chữ số trên cột" / "chữ viết tay…" / "chữ ký…" / "text box" → giữ nguyên cả câu ✅
"Không có chữ, nền xanh"                        → giữ lại "nền xanh" ✅
"Không có bất kỳ chữ nào" / "Không có chữ trên ảnh" → loại cả câu ✅
"Không chèn text và watermark, cột điện màu cam" → giữ lại "cột điện màu cam" ✅
"Không có âm thanh nào, nền xanh"               → giữ lại "nền xanh" ✅
```

Các test hiện có vẫn qua. Còn sót một điểm: "Không chèn chữ lên ảnh" để lại "lên ảnh". Có thể nuốt thêm `(?:\s+(?:lên|trên)\s+(?:ảnh|video|hình))?` sau `textTerms` trong `negatedTextPattern`.

## 3. Lưu ý (không chặn)

### 3.1. Xóa prompt giờ âm thầm xóa cả lịch sử version

`App.tsx` giờ gán `promptId` khi commit nếu nội dung **trùng khớp hoàn toàn** với một prompt đã lưu. Khi xóa prompt, mọi version mang `promptId` đó bị xóa luôn, cả cục bộ lẫn trên server, mà **không hỏi**. Hai rủi ro:

- Bạn chỉ muốn dọn thư viện prompt, nhưng mất luôn các commit trong cây version. Đây là dữ liệu không lấy lại được, trừ khi còn trong backup.
- Version con có `parentId` trỏ tới version đã xóa sẽ thành "mồ côi" trong cây nhánh.

**Đề xuất:** hiện hộp xác nhận "Xóa cả N phiên bản liên quan?" với hai lựa chọn: xóa cả hai, hoặc chỉ xóa prompt và gỡ `promptId` khỏi các version. Ngoài ra, `queueDeletion('versions', …)` có trả về `false` khi không ghi được hàng đợi, nhưng kết quả đang bị bỏ qua. Nên xử lý giống phần xóa prompt.

### 3.2. Văn bản bôi chọn khi panel đang đóng luôn vào tab Tiêu chuẩn

Khi panel mở và nạp `lpromptSelectionImport` trong lúc hydrate, `applySelection` đọc `activeTabRef.current`. Ref này chỉ được cập nhật sau lần render tiếp theo, nên lúc đó vẫn là giá trị mặc định `'standard'`, kể cả khi tab đã lưu là Thi Công. Lỗi này nhẹ. Có thể truyền `savedTab` vào `applySelection` trong lúc hydrate.

### 3.3. Server import nhiều file `.ts` hơn

Giờ cả `mcpServer.js` lẫn `presetsData.js` đều import từ `src/`. Đã có quyền đọc và test import bằng Node thật, nên ổn. Chỉ cần nhớ rằng mọi import trong `src/services/evaluator.ts` và `src/data/fabricPresets.ts` phải là `import type` hoặc có đuôi `.ts`. Test `server-node-import` sẽ bắt lỗi nếu vi phạm, nên nên mở rộng test này để nạp cả `presetsData.js`.
