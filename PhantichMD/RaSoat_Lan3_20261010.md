## 2. Lỗi cần sửa

### 2.1. (Cao) Bản biên dịch biến mất ngay sau khi bấm "Biên dịch"

**Vị trí:** `extension/ExtensionPanel.tsx`, `storageListener` mới trong effect `[activeTab, saveConstructionDraft]` (khoảng dòng 307–322).

`chrome.storage.onChanged` được phát cho **mọi** trang của extension, kể cả chính trang vừa ghi. Listener mới không phân biệt ai đã ghi, nên:

1. Bạn bấm **Biên dịch prompt cục bộ**. `compile()` gọi `setCompiled(result)` rồi `saveDraft(...)`, và `saveDraft` ghi vào `lpromptDraft`.
2. `onChanged` phát lại cho chính panel. Listener thấy `newValue.source` có nội dung, nên gọi `setSource(...)`, **`setCompiled(null)`** và đổi trạng thái thành "Đã nhận phần văn bản được chọn từ menu chuột phải".
3. Phần xem trước bản biên dịch, nút **Chèn vào Gemini** và **Sao chép** biến mất.

**Bằng chứng:** Tôi render `ExtensionPanel` trong jsdom với một `chrome.storage` giả, phát `onChanged` giống Chrome thật. Sau khi bấm Biên dịch, khu vực kết quả **không hiển thị**, và dòng trạng thái là "Đã nhận phần văn bản được chọn…". Tôi tắt việc phát `onChanged` và chạy lại cùng phép thử thì khu vực kết quả hiển thị bình thường.

Cùng nguyên nhân gây ra thêm các lỗi phụ:
- **Gõ phím:** mỗi phím gõ gọi `saveDraft`. Sự kiện `onChanged` của phím trước có thể về sau phím hiện tại, nên `setSource` đặt lại giá trị cũ. Hậu quả là mất ký tự hoặc con trỏ nhảy về cuối khi bạn sửa giữa đoạn văn. Đây là suy luận từ code, tôi chưa đo trên Chrome thật.
- **Đổi Domain hoặc ngôn ngữ:** cũng xóa bản biên dịch.
- **Tab Thi Công:** khi bridge từ web app ghi `lpromptDraft`, listener ghi đè **bối cảnh thi công** bằng prompt của tab Tiêu chuẩn.
- Context menu kích hoạt cả message lẫn storage listener, nên văn bản được nạp hai lần. Việc này vô hại nhưng thừa.

**Đề xuất:** dùng một khóa riêng chỉ dành cho văn bản nhận từ menu chuột phải, và panel chỉ nghe khóa đó.

```ts
// serviceWorker.ts (trong handler contextMenus.onClicked)
const importId = crypto.randomUUID();
void chrome.storage.local.set({ lpromptSelectionImport: { id: importId, source, at: Date.now() } });
// (giữ nguyên phần cập nhật lpromptDraft và sendMessage nếu muốn)

// ExtensionPanel.tsx
const lastSelectionImportIdRef = useRef('');
const applySelection = (id: string, text: string) => {
  if (!id || id === lastSelectionImportIdRef.current) return;   // chống nạp 2 lần
  lastSelectionImportIdRef.current = id;
  // ... phần setSource / setConstructionContext như hiện tại
};

const storageListener = (changes: Record<string, chrome.storage.StorageChange>, areaName: string) => {
  if (areaName !== 'local') return;
  const next = changes.lpromptSelectionImport?.newValue as { id?: string; source?: string } | undefined;
  if (next?.id && next.source) applySelection(next.id, next.source);
};
```

Khi đó message `LPROMPT_DRAFT_UPDATED` cũng nên mang `id` để gọi chung `applySelection`. Khi panel mở, nên đọc `lpromptSelectionImport` một lần và chỉ áp dụng nếu `at` còn mới (ví dụ dưới 10 giây). Nên thêm một test jsdom như mô tả ở trên: bấm Biên dịch thì phần kết quả vẫn còn.

**Nếu cần sửa tạm ngay:** chỉ xử lý khi `newValue.source !== oldValue?.source` **và** khác `source` hiện tại (đọc qua ref). Cách này chặn được lỗi Biên dịch và đổi Domain, nhưng vẫn còn race khi gõ và lỗi ghi đè tab Thi Công. Vì vậy nên dùng khóa riêng.

### 2.2. (Trung bình) Phủ định "chữ" làm hỏng câu vì thiếu ranh giới từ

**Vị trí:** `src/services/constructionPromptCompiler.ts`, `textTerms` và `negatedTextPattern`. `negatedMedia` cũng có cùng vấn đề.

Kết quả thử:

```
"Không có chữ ký trên biên bản nghiệm thu"     → duplicate-no-text, giữ lại "ký trên biên bản nghiệm thu"   ❌
"Không có textures nhòe"                       → duplicate-no-text, giữ lại "ures nhòe"                     ❌
"Tuyệt đối không có watermark, nền trời xanh"  → giữ lại "nền trời xanh"                                    ✅
"Không chèn text và watermark, cột điện màu cam" → giữ lại "cột điện màu cam"                               ✅
```

"chữ" khớp phần đầu của "chữ ký", và "text" khớp phần đầu của "textures". Phần còn lại bị cắt và giữ lại thành câu vô nghĩa trong prompt.

**Đề xuất:** thêm ranh giới Unicode sau cụm từ, cho cả chữ và âm thanh:

```ts
const END = '(?![\\p{L}\\p{N}])';
const textTerms = `(?:phụ đề|watermark|text|chữ(?:\\s*trên\\s*(?:ảnh|video))?)${END}`;
const mediaTerms = `(?:âm thanh|nhạc nền|giọng đọc|thu âm|thời lượng|\\d+\\s*giây)${END}`;
```

Nên thêm test cho "Không có chữ ký…" (không được báo `duplicate-no-text`, phải giữ nguyên cả câu).

Đợt này cũng **thu hẹp** việc nhận diện "không chèn chữ". Regex cũ là `(không|cấm…).{0,40}(chữ…)`, regex mới yêu cầu từ phủ định đứng sát. Kết quả là các câu sau không còn được nhận ra là trùng quy tắc, và bị giữ lại trong prompt:

```
"Không được chèn chữ lên ảnh"  → [] (giữ nguyên)
"Không hiển thị phụ đề"        → [] (giữ nguyên)
"Không có bất kỳ chữ nào"      → [] (giữ nguyên)
```

Việc này không gây lỗi biên dịch, chỉ làm prompt có câu lặp với quy tắc có sẵn. Có thể bổ sung `được`, `hiển thị`, `bất kỳ` vào nhóm động từ tùy chọn:
`(?:không|cấm|tuyệt đối không)\s+(?:được\s+)?(?:có\s+|cần\s+|chèn\s+|thêm\s+|hiển thị\s+)?(?:bất kỳ\s+)?${textTerms}`.

### 2.3. (Trung bình) `server/mcpServer.js` import thẳng file TypeScript

**Vị trí:** `server/mcpServer.js:7`, dòng `import … from '../src/services/evaluator.ts'`.

Cách này chạy được vì Node 22.18+ và 24 tự bỏ phần type của file `.ts`. Tôi đã thử `import('./server/mcpServer.js')` bằng Node 22.22 và nó chạy bình thường. Tuy vậy, có ba rủi ro:

1. **Windows Service có thể không đọc được `src/`.** `Install-LPromptService.ps1` chỉ cấp quyền đọc cho tài khoản `LocalService` trên `server`, `dist`, `node_modules` và `runtime`, không có `src`. Nếu thư mục `D:\DevV2\LPrompt` không kế thừa quyền đọc cho `LocalService`, service sẽ lỗi ngay khi khởi động vì không import được `evaluator.ts`. Đây là suy luận, tôi chưa chạy được service trên máy bạn. Hiện `service\windows\runtime` trên máy bạn đang trống, nên có vẻ service chưa được cài lại sau đợt sửa này.
2. **Dễ hỏng âm thầm khi sửa sau.** Node chỉ chấp nhận cú pháp TypeScript "xóa được" và yêu cầu đường dẫn import có đuôi `.ts`. Chỉ cần sau này `evaluator.ts` import thêm một module thường không có đuôi (ví dụ `'../utils/x'`) hoặc dùng `enum`, server sẽ lỗi khi chạy thật. Trong khi đó, vitest vẫn qua vì Vite tự biên dịch file.
3. Bản `tsconfig` của web app không kiểm tra `server/`, nên không có gì báo lỗi sớm.

**Đề xuất, chọn một trong hai:**
- **Đơn giản:** thêm `(Join-Path $script:LPromptRoot 'src')` vào `$readTargets` trong `Install-LPromptService.ps1`. Thêm một test chạy Node thật, không qua vitest, để chặn lỗi ở rủi ro 2:
  ```js
  // tests/server-node-import.test.js
  import { execFileSync } from 'node:child_process';
  it('server modules load in plain Node', () => {
    execFileSync(process.execPath, ['-e', "import('./server/mcpServer.js').then(m => { if (typeof m.evaluatePromptLocally !== 'function') process.exit(1); })"], { stdio: 'pipe' });
  });
  ```
- **Bền hơn:** tách phần chấm điểm ra một file JavaScript thuần dùng chung, ví dụ `shared/evaluator.js` có JSDoc types, để `src/` và `server/` cùng import. Cách khác là build `server/` bằng Vite hoặc esbuild vào `dist-server/`. Với cách này, service chỉ cần quyền đọc các thư mục đã có.

### 3.2. Backup

- Logic chống ghi dồn đúng: lần đầu ghi ngay, các lần trong vòng 60 giây được gộp thành một lần ghi bù. `closeDatabase` ghi nốt nếu còn lịch, và `.unref()` không giữ process.
- Mỗi ngày chỉ có một file `lprompt_snapshot_YYYYMMDD.json`, nên "giữ 10 file" nghĩa là giữ 10 ngày. Như vậy là ổn.
- File `lprompt_full_backup_*.json` do `POST /api/backup` tạo **không** được dọn, vì hàm prune chỉ lọc tiền tố `lprompt_snapshot_`. Nếu bạn hay bấm backup thủ công thì nên dọn cả loại này, ví dụ giữ 20 file.
- Chưa có test cho phần chống ghi dồn và dọn file. Có thể thêm test dùng `vi.useFakeTimers()` cùng một thư mục `LPROMPT_DATA_DIR` tạm.

### 3.3. Xóa version theo prompt

`deletePrompt` giờ xóa thêm `prompt_versions WHERE prompt_id = ?`. Tuy vậy:
- **Web app không bao giờ gán `promptId` khi commit version.** Chỉ REST API nhận trường này, và không có code nào trong `src/` gửi nó. Vì vậy, thay đổi này hiện gần như không có tác dụng.
- Nếu sau này có version mang `promptId`, chúng vẫn nằm trong `localStorage` của web app. Lần mở web app tiếp theo, đoạn đồng bộ ở `App.tsx:170–174` sẽ thấy "version cục bộ chưa có trên server" và **tải lại lên**, khiến chúng sống lại. Khi đó web app cũng cần xóa version cục bộ theo `promptId` và đưa chúng vào outbox xóa.
- Hai câu `DELETE` nên nằm trong một transaction (`BEGIN … COMMIT`) để không xóa dở dang.
